## Findings

**做得好的**
1. 初始诊断做得好：4 项安全隐患全部列出（伪造 Cookie / unknown identity / expired session / probe Warning），F1 满分。
2. voice 显式会话修住；本机 worker 例外收窄为白名单接口——思路正确。
3. build real_pass；¥1.09/26min（后台核实），与 minimal/opencode 同档。

**回落点**
1. **ambient 没收住**——PR 里自己写了 `[probe:Warning]` 提示隐式 ambient 依赖，但只在 voice 侧显式化，`build_chat_context_v3` 的 ambient 静默回退没堵住 → F3-05 掉。
2. MQTT publish 静态未识别（可能与 win32/pwsh 下模型写的 API 形态有关）。
3. backfill / wifi_ssid / F12 为常规短板。

## 结论
- **DSH standard (win32) + v4f = 90/B+**，与 opencode（92）、reasonix（92）同级——**official harness 在 Windows standard 下没有带来提升**。
- 注意：**这不是官方跑分的配置**（官方 = minimal + max + Linux/Landlock）。Windows standard 的 pwsh 后端、非 minimal 预设都会稀释 harness 加成。
- **是否冤枉 DSH 待 WSL minimal 枪验证**——若 WSL minimal+max 明显高于 90，则 harness 差异真实存在；若仍在 90 上下，则"强无敌跑分"是环境/预设红利。
