## 摘要

DSH 极简第二轮 **96/96/B+**，比首发（99/99/A）低 3 分。hidden 维持高位（44/45），
但 **ESP static 从 9/9 掉到 6/9**，丢分全部在 ESP 契约命名上。

## hidden：44/45

- 唯一败项 `V4-F12-04`（-1，semantic）：no-actor 场景返回 `not_authenticated`
  而非 `not_authorized_for_target`。**与首发、与 Gemini-3.7 完全同一处**——这是
  模型/基准的稳定语义差异点，行为层（V4-F3-04）两轮都过。
- **ambient 两轮连过**（V4-F3-05 5 分）：显式 session 模式稳定复现，非偶发。

## ESP-IDF：static 6/9（-3）+ real build passed

| 丢分项 | 原因 |
|---|---|
| V4-F8-03 mqtt deps | CMake REQUIRES 写成 `espressif__mqtt`（管理组件全名），测试契约查 `mqtt`。IDF 实际能编译（build 过），但文本契约不匹配 |
| V4-F8-05 publish 标记 | 代码用 `esp_mqtt_client_enqueue` 发送，测试要 `esp_mqtt_client_publish` 标记 |
| V4-F8-08 就绪检查 | device_config `complete()` 未显式校验 `wifi_ssid` |

根因：模型参考了错误的组件命名先例（REQUIRES 应写 `mqtt` 组件名，
idf_component.yml 才写 `espressif/mqtt` 管理依赖）。**与 t4（opencode 正式版 93，
ESP 4 处掉分）模式相同**——ESP 契约命名是 v4pro 家族稳定弱点。

real build 仍 passed：stdpro.bin 979,856 字节，sha256 `5f93ef09...`，已存证。

## PR 质量

初始 6 项诊断 + voice ambient 预警 + ESP baseline 说明完整；文档十处同步；
架构分层清晰。F1 全过。

## 结论

- **两轮 DSH 极简：99 / 96**。方差 3 分，全部来自 ESP 契约命名（mqtt 组件名、
  publish 函数名、wifi_ssid 就绪检查）。
- **hidden 侧稳定在 44–45/45**（唯一共性败项 F12-04 语义字符串）。
- 若修掉"REQUIRES 写组件全名"的命名习惯，v4pro 极简枪可达 99 级稳定。
