# V4 反偏置与出题纪律

## 1. 问题陈述

题面主体曾由 GPT 体系参与设计。早期高分集中在 GPT，引发合理怀疑：

> 是模型更强，还是「出题人 = 答题人分布」？

后续 GLM-5.2 / Grok-4.5 等达到 95–96，说明 **并非 GPT 锁死满分**；但下列 **软偏置** 仍可能存在：

| 偏置类型 | 表现 |
|----------|------|
| 契约措辞 | 精确 reason 枚举、特定 JSON 字段名 |
| 过程叙事 | 长 PR、完整 debug 故事 |
| 补全形态 | 按 reference 清单补 MQTT/NVS |
| Marker 评分 | static 关键词命中 |
| 单点 cap | 放大「谁先想到 ambient」 |

V4 用纪律压偏置，而不是假装偏置为零。

## 2. 出题十一条纪律（强制）

1. **行为不变量优先**  
   Oracle 必须是：输入 → 可观察输出/DB/HTTP 状态。禁止「必须使用函数名 `foo`」。

2. **多种正确实现**  
   每条 ≥2 分的 item 须在 `allowed_equivalents` 写至少一种替代形态（模块拆分、不同存储、不同 HTTP 状态码 401 vs 403 等）。

3. **字符串语义降权**  
   reason / 错误码文案最多进 F12（4 分），不得 hard cap。

4. **禁止参考实现克隆检测**  
   不得用「diff 像不像完成版」打分；完成版仅供出题人自测。

5. **真实风险映射**  
   每题对应真实项目风险（隐私、迁移、构建、兼容）。禁止纯脑筋急转弯。

6. **低耦合**  
   单点失败不得设计为必然导致 ≥3 个无关 family 全灭（V1 auth 连坐教训）。

7. **症状 ≠ 根因配方**  
   ONBOARDING/probe 给现象；根因留给推理。

8. **防刷分**  
   对 static marker 类检查，必须搭配 build 或运行时路径证据；报告 overclaim 独立罚。

9. **跨模型试跑门禁（冻结 seed 前）**  
   至少 1 个 **非主要出题模型** 完整 blind run；记录是否「只有一家能看懂题面」。异常则改题而非改分吹毛求疵。

10. **变更审计**  
    每加一题：写 item 规格 → 写测试 → 自测 broken/fixed → 更新 registry → 更新交叉审核笔记。

11. **门槛聚集审计**  
    冻结前用历史重标注和 3–5 个夹具模拟 Ship/Ability 分布；若超过约三分之一的可用样本因同一非信任 gate 贴在同一 Ship 分，应调低该 gate 的排序权重、提高展示 Ability 的优先级，或改成 Class-only 标记。

## 3. 评分反偏置

| 做法 | 作用 |
|------|------|
| Ship/Ability 双轨 | 避免「像 GPT 的报告文风」独占叙事 |
| Channel 列 | 工具偏置可见 |
| 人工审查 overclaim | 压「会写不会做」 |
| F9 真实 build | 压「marker 工程师」 |
| 部分分 | 压「全有或全无」的 GPT 式清单完成 |
| 门槛聚集审计 | 防止 V3.1 式 cap 换皮复发 |

## 4. 作者与评审角色分离（流程）

建议角色：

| 角色 | 职责 |
|------|------|
| Item Author | 写题与 oracle |
| Adversarial Reviewer（另一模型/人） | 专门找「只对某家友好」的点 |
| Seed Maintainer | 保证 public 绿、hidden 预期红 |
| Score Auditor | 抽查 Ability 草稿与人工分偏差 |

同一模型不宜既最终定稿题库又当唯一试跑样本。

## 5. 「像 GPT 的题」自检表

出题后逐条问：

- [ ] 若模型拒绝正确但 reason 写成近义英文，是否仍给 F3 满分？**应是**  
- [ ] 若 MQTT 封装在不同文件/命名，static 是否仍过？**应是**  
- [ ] 若 401 代替 403，是否误杀？**应否**  
- [ ] 是否只有读过某篇英文博客才知道的冷知识？**应避免**  
- [ ] 是否在惩罚「没按我的模块切分」？**应否**  

## 6. 与「变难」的边界

反偏置 **不是** 把题变简单：

- ambient fallback、迁移保真、跨模块 bridge 仍然要考，且要拉开中上。  
- 变的是 **计分表达** 与 **oracle 形态**，不是取消难题。  

## 7. 文档与实现的一致性

`docs/v4` 通过后，实施必须：

- hidden 断言与 item 规格一致  
- reviewer_prompt 不鼓励「按 GPT 参考实现打分」  
- rubric 不恢复 82 单点硬顶  
- scoreboard 不把 Ship gate 同分组写成模型能力同分  

若实施漂移，以 **已审核的 item bank + scoring** 为准回滚代码。
